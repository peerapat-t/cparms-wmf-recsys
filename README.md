# CPARMS_WMF

**Author:** Peerapat Tancharoen, KMITL

CPARMS_WMF is a notebook-driven recommendation experiment under sparse implicit feedback.
It compares standard Weighted Matrix Factorization (WMF) with WMF variants that
use item co-occurrence signals or CPARMS association rule signals. The experiment
and its dataset EDA export are generated by `notebook_experiments.ipynb`.

## Models

The default experiment enables a popularity baseline and three fitted WMF models.

| Notebook key | Model | Implementation | Role |
| --- | --- | --- | --- |
| `01 mostpop` | MostPop | `model/base_model/mostpop.py` | Deterministic global positive-popularity baseline. |
| `02 standard_wmf` | Standard-WMF | `model/base_model/wmf_standard.py` | ALS-trained implicit-feedback WMF. |
| `03 cofactor_wmf` | CoFactor-WMF | `model/signal_gen/generator_sppmi.py`, `model/base_model/wmf_cofactor.py` | WMF with shared item factors regularized by item-item SPPMI reconstruction. |
| `04 cparms_wmf` | CPARMS-WMF | `model/signal_gen/generator_cparms.py`, `model/base_model/wmf_cparms.py` | WMF regularized toward a sparse CPARMS user-item signal. |

## Feedback Matrices

`util/feedback.py` centralizes the conversion from raw ratings to the matrices
used by training and evaluation:

```text
Y = raw non-negative ratings, values preserved
B = seen interactions, where Y != 0 becomes 1
L = liked interactions, where Y > 3.0 becomes 1
```

Ratings strictly greater than `3.0` are positive feedback. For integer star
ratings, this is equivalent to keeping ratings `4` and `5` as positives.
Ratings `1`, `2`, and `3` remain in `Y` and `B`, so they still affect duplicate
collapse and seen-item masking, but they are not positive WMF, CPARMS, SPPMI,
activity-group, validation, or test targets.

## Methods

### Standard-WMF

`WMF_Standard` factorizes the binary positive-feedback matrix `L` with ALS.
Unobserved and non-positive pairs use confidence `1`; positive pairs use
confidence `1 + alpha`. The model stores user factors in `P`, item factors in
`Q`, and scores a user with `Q @ P[user_idx]`.

### CPARMS Signal

`Generator_CPARMS` builds a sparse user-item signal from a training matrix:

1. Canonicalize raw feedback as `Y`, seen interactions as `B`, and liked
   interactions as `L`.
2. Add individual liked-item tokens from `L`.
3. Optionally fit KMeans user clusters on active positive-history rows and add
   user-cluster tokens.
4. Optionally fit KMeans item clusters on active positive-history item rows and add
   liked-item-cluster presence tokens (E).
5. Combine token blocks in the transaction layout `[L | U | E]`.
6. Count directional token pairs and keep only rules whose consequent
   is an individual item token; cluster tokens provide antecedent context only.
7. Filter rules by `min_support`, `min_confidence`, and `min_lift`.
8. Score retained rules by rule `confidence`.
9. Split confidence contributions into generic user-cluster rules and
   personalized item/item-cluster rules, then remove previously seen items
   from both families.
10. Add the generic and personalized rule-confidence contributions into item
    scores.
11. Optionally normalize with per-row `row_max` or log-damped per-row
    `log_row_max` (`log1p` before row-max scaling).

`WMF_CPARMS` adds a signal reconstruction term over the nonzero entries of the
CPARMS signal matrix `S`, weighted by `gamma`.

### CoFactor Signal

`build_item_sppmi_matrix()` builds an item-item SPPMI matrix from positive
training history. It counts off-diagonal item co-occurrences, converts counts to
PMI, and keeps positive values after subtracting `log(negative_samples)`.

`WMF_Cofactor` combines WMF user-item reconstruction with item-item SPPMI
reconstruction. It updates user factors, item factors, context factors, and
item/context co-occurrence biases. If `fit()` receives no item-item matrix and
`gamma > 0`, it builds SPPMI internally; the final test notebook builds SPPMI
explicitly for positive `gamma` so signal-generation runtime can be logged separately.

The paper scales the WMF part of the objective by a relative scale `ell`. This
implementation uses the algebraically equivalent `gamma = 1 / ell` on the
co-occurrence part. To preserve the same objective after rescaling,
`lambda_context_rate` is set to `gamma * lambda_rate`.

## Experiment Workflow

`notebook_experiments.ipynb` runs the complete experiment:

1. Load selected CSV files from `database/csv/`.
2. Sort all events globally by `timestamp`, using original row order to break
   timestamp ties.
3. Split rows into chronological train, validation, and test partitions targeting
   `70/10/20` ratios. Cut points are snapped to the nearest unique-timestamp
   boundary, so no single timestamp straddles two partitions and the realized
   ratios can drift slightly from the targets.
4. Index tuning matrices from train-window users and items, dropping validation
   events on unknown users or items.
5. Run reproducible random hyperparameter search for each seed.
6. Select each seed/dataset/model configuration by validation `NDCG@10`.
7. Re-index final matrices from train+validation users and items, dropping test
   events on unknown users or items.
8. Retrain the selected configuration on train + validation.
9. Evaluate on test at `K = 10, 20, 50, 100, 200`.
10. Export an Excel workbook with `results`, `mean_sd`, and `dataset_eda` sheets.

The split is **fit-window-restricted**: the model universe is fixed by the fit window alone.
Users and items that first appear in a future evaluation window are never padded
into the fit matrix as empty rows/columns, so they cannot influence learned
parameters (such as association rule support denominators) and cannot appear as
candidate items. Tuning matrices contain only users/items known in train; final
matrices contain only users/items known in train+validation.

The CSV inputs are expected to be deduplicated at the `userid,itemid` level.
`_build_sparse_matrix()` still defensively collapses duplicate user-item events
inside a partition to their maximum rating.

## Default Configuration

| Setting | Value |
| --- | --- |
| Notebook | `notebook_experiments.ipynb` |
| Experiment seeds | `42`, `43`, `44`, `45`, `46` |
| Random-search rounds | `30` per seed |
| Split ratios | `70/10/20` train/validation/test |
| Ranking cutoffs | `10`, `20`, `50`, `100`, `200` |
| Selection metric | Validation `NDCG@10` |
| User groups | `interaction_1`, `interaction_2`, `interaction_3_plus` |
| Enabled datasets | `01_amz_beauty`, `02_amz_industry`, `03_amz_pantry`, `04_amz_music`, `05_amz_instruments` |
| Enabled models | `01 mostpop`, `02 standard_wmf`, `03 cofactor_wmf`, `04 cparms_wmf` |
| Output workbook | `results/final_results_<utc_timestamp>.xlsx` |
| Output sheets | `results`, `mean_sd`, `dataset_eda` |

Within each random-search round, the WMF variants share sampled `latent`,
`lambda_rate`, `n_sweeps`, and `alpha`. CPARMS-WMF and CoFactor-WMF sample
separate `gamma` values. CoFactor-specific parameters are drawn from their own
random stream, independent of the shared stream used by standard WMF and CPARMS,
so adding or removing CoFactor cannot shift the values the other models receive.
`random_state` is not sampled: every WMF variant, and the KMeans step inside the
CPARMS generator, receives the experiment seed itself, so factor initialization
is identical across models within a seed. MostPop is deterministic and takes no
seed.

## Hyperparameter Search Space

| Parameter | Values |
| --- | --- |
| `latent` | `10`, `20`, `30`, `40` |
| `lambda_rate` | `0.0001`, `0.001`, `0.01`, `0.1` |
| `n_sweeps` | `15`, `20`, `25`, `30` |
| `alpha` | `10.0`, `20.0`, `40.0`, `80.0` |
| CPARMS `gamma` | `0.5`, `1.0`, `2.0`, `4.0` |
| CoFactor relative scale `ell` | `0.01`, `0.05`, `0.1`, `0.5`, `1.0`, `5.0`, `10.0` |
| CoFactor `gamma = 1 / ell` | `100.0`, `20.0`, `10.0`, `2.0`, `1.0`, `0.2`, `0.1` |
| `normalize` | `row_max`, `log_row_max` |
| `k_user` | `1`, `2`, `3`, `5` |
| `K_item` | `1`, `2`, `3`, `5` |
| `min_support` | `0.0`, `0.00005`, `0.0001`, `0.0003` |
| `min_confidence` | `0.0`, `0.0005`, `0.001`, `0.002` |
| `min_lift` | `0.0`, `0.2`, `0.5`, `0.8` |
| CoFactor `lambda_context_rate` | `gamma * lambda_rate` |
| `negative_samples` | `1`, `2`, `5`, `10`, `50` |

The three rule-filter thresholds are sampled independently, so the random search
can explore cross-combinations of rule coverage, confidence, and lift filtering.

## Evaluation

`experiments/all_ranker.py` computes NDCG for users with positive history and at
least one relevant evaluation item (`rating > 3.0`). The fit-window splitter has
already removed unknown users and items before ranking. All items stored in the
training matrix are removed from each user's candidate list, including ratings
`1`, `2`, and `3`. Score ties are resolved deterministically by item index.

Historical activity groups are built from positive interactions in `L`:

| Group | Historical interactions |
| --- | --- |
| `interaction_1` | 1 |
| `interaction_2` | 2 |
| `interaction_3_plus` | 3 or more |

## Output Workbook Structure

The experiment writes `results/final_results_<utc_timestamp>.xlsx`, where the
timestamp is generated in UTC with `%Y%m%d_%H%M%S`.

### `results`

One row is written for each final test run: `seed` x `dataset_name` x enabled
`model`.

Non-metric columns for the default model set:

```text
seed
dataset_name
model
s_mat_runtime
wmf_runtime
total_runtime
n_iter_random_search
selection_metric
selection_k
validation_selection_score
n_users_eval
n_positive_targets
latent
lambda_rate
n_sweeps
alpha
random_state
gamma
lambda_context_rate
negative_samples
k_user
K_item
min_support
min_confidence
min_lift
normalize
```

Parameter columns depend on the enabled models; unused model-specific parameter
columns are blank. Because MostPop is not tuned, its rows carry no hyperparameter
values and its `validation_selection_score` is `NaN`. `s_mat_runtime` is `0` for
every model that generates no signal matrix: MostPop and Standard-WMF never build
one, and CoFactor skips it only in the degenerate `gamma = 0` case. The default
hyperparameter search never samples that case — CoFactor draws `gamma = 1 / ell`
with `ell` in `{0.01, ..., 10}`, so `gamma > 0` on every trial and CoFactor always
builds an SPPMI matrix with a nonzero `s_mat_runtime`. Runtime values are recorded
in minutes.

Metric columns are appended in cutoff order for each `K` in
`10, 20, 50, 100, 200`:

```text
ndcg_all@K
ndcg_user_interaction_1@K
ndcg_user_interaction_2@K
ndcg_user_interaction_3_plus@K
```

### `mean_sd`

One row is written for each `dataset_name` x `model`. This sheet aggregates the
metric and runtime columns from `results` across seeds.

Identifier columns:

```text
dataset_name
model
seed_count
```

`seed_count` is the number of distinct seeds contributing to the row, so a
partial run is visible in the sheet itself.

Aggregate columns follow this naming pattern:

```text
<metric_or_runtime>_mean
<metric_or_runtime>_sd
```

The aggregated fields are every NDCG column listed above plus:

```text
s_mat_runtime
wmf_runtime
total_runtime
```

The `_sd` columns are the sample standard deviation across seeds (pandas `std`,
`ddof=1`). They are written as values, not formulas. A single-seed run leaves
them blank (`NaN`).

### `dataset_eda`

Three rows are written for each enabled dataset in the final results workbook,
one for each `raw`, `val`, and `test` split:

```text
dataset_name
split
n_users
n_items
n_interactions
n_users_eval
interaction_1
interaction_2
interaction_3_plus
density_pct
sparsity_pct
```

The `raw` row describes the full input dataset; its evaluation and activity-group
fields are blank. The `val` and `test` rows describe interactions retained after
fit-window filtering, counting only users and items active in each evaluation
matrix. Validation activity groups use positive train history and a positive
validation target; test groups use positive train+validation history and a
positive test target. Density is `interactions / (users * items) * 100`, and
sparsity is `100 - density`.

## Datasets

`SELECTED_DATASETS` maps a notebook key to a CSV path. All five are enabled:

| Notebook key | File |
| --- | --- |
| `01_amz_beauty` | `database/csv/dataset_amazon_lux_beauty_5_core.csv` |
| `02_amz_industry` | `database/csv/dataset_amazon_industry_5_core.csv` |
| `03_amz_pantry` | `database/csv/dataset_amazon_pantry_5_core.csv` |
| `04_amz_music` | `database/csv/dataset_amazon_music_5_core.csv` |
| `05_amz_instruments` | `database/csv/dataset_amazon_instruments_5_core.csv` |

Each CSV must contain these columns (additional columns are ignored):

```text
userid,itemid,timestamp,rating
```

Input constraints enforced by `get_temporal_split()`:

- No nulls in any of the four columns.
- `timestamp` must be datetime-typed or ISO-8601 strings (e.g. `2016-11-07`).
  A numeric column is rejected rather than guessed, because its epoch unit
  (s / ms / us / ns) is ambiguous and a wrong guess would silently move every
  cutoff date. Convert with `pd.to_datetime(col, unit=...)` beforehand.
- `rating` must be numeric, finite, and non-negative. The shipped datasets use
  integer stars `1`-`5`.
- At least three distinct timestamp groups must exist, since cut points are
  snapped to unique-timestamp boundaries.

To change datasets, edit `SELECTED_DATASETS` in `notebook_experiments.ipynb`.
To change which models run, edit `MODEL_PARAM_KEY`. It lists every model in report
order and maps each one to its key in a hyperparameter sample; MostPop maps to `None`
because it has nothing to tune, so the random search skips it and it is fitted only at
final-test time.

The supplied CSV files can be regenerated from the Amazon 5-core JSON Lines dumps
in `database/json/` with `database/preprocess.py`. The preprocessing step keeps the four required
fields, converts Unix timestamps to datetimes, drops incomplete rows, and keeps the
earliest review for each `userid,itemid` pair (breaking timestamp ties by higher rating), so a
later re-review cannot move a user's first observed interaction into a later temporal split.
No k-core filter is re-applied after deduplication: the `_5_core` suffix refers to the
published 5-core source dumps, and collapsing duplicate `userid,itemid` pairs can leave
some users or items with fewer than five remaining rows.

## Results

The canonical results workbook is `results/final_results_20260717_190810.xlsx`,
produced by a full run of the default configuration above (5 seeds x 5 datasets x
4 models, 30 random-search rounds per seed). All numbers below are
mean ± sample standard deviation across the five seeds; MostPop is deterministic,
so its standard deviation is always `0` and is omitted.

### Overall ranking quality (`ndcg_all@10`)

| Dataset | MostPop | Standard-WMF | CoFactor-WMF | CPARMS-WMF |
| --- | --- | --- | --- | --- |
| `01_amz_beauty` | 0.0025 | 0.0427 ± 0.0026 | 0.0433 ± 0.0026 | **0.0465 ± 0.0018** |
| `02_amz_industry` | 0.0258 | 0.0183 ± 0.0011 | 0.0186 ± 0.0004 | **0.0289 ± 0.0005** |
| `03_amz_pantry` | 0.0144 | 0.0184 ± 0.0007 | 0.0178 ± 0.0017 | **0.0197 ± 0.0011** |
| `04_amz_music` | 0.0044 | 0.0172 ± 0.0005 | 0.0174 ± 0.0005 | **0.0183 ± 0.0004** |
| `05_amz_instruments` | 0.0211 | 0.0195 ± 0.0004 | 0.0203 ± 0.0007 | **0.0259 ± 0.0010** |

### Findings

- CPARMS-WMF has the best `ndcg_all@10` mean on every dataset, from +6.4% over
  Standard-WMF on Music to +58.4% on Industrial & Scientific, and it keeps the
  best mean at every deeper cutoff (`@20`-`@200`) as well. It wins 73 of 75
  overall dataset-seed comparisons (25/25 vs MostPop, 24/25 vs each WMF
  baseline); the only overall losses are on Pantry under seed `45` against
  both WMF baselines.
- MostPop is a serious baseline: it beats both Standard-WMF and CoFactor-WMF
  outright on Industrial (0.0258 vs 0.0183/0.0186) and Instruments
  (0.0211 vs 0.0195/0.0203). CPARMS-WMF nevertheless beats MostPop on every
  dataset mean and in every overall dataset-seed run.
- The MostPop comparison depends on user history. In the `interaction_1`
  group, MostPop keeps the best mean on Industrial (0.0687 vs 0.0658) and
  Instruments (0.0458 vs 0.0385), CoFactor-WMF is best on Beauty
  (0.0979 vs 0.0924) and Music (0.0187 vs 0.0176), and CPARMS-WMF is best only
  on Pantry (0.0223 vs 0.0211). CPARMS-WMF has the best mean in every
  `interaction_3_plus` group, so its advantage over popularity grows with
  history. Popularity being hard to beat at a single interaction is expected
  of a strong top-N baseline at extreme sparsity; the headline result is the
  overall gain over every baseline, and a history-aware blend is a natural
  next step rather than a sign the personalized comparison fails.
- Against the personalized WMF baselines, CPARMS-WMF beats Standard-WMF in
  21/25 and CoFactor-WMF in 19/25 `interaction_1` dataset-seed runs. Its
  largest `interaction_1` mean gains over Standard-WMF are on Industrial
  (+143%) and Instruments (+68%); on Beauty and Music that group stays close
  to the WMF baselines (-3% and +1% vs Standard-WMF).
- CoFactor-WMF is ahead of Standard-WMF on four of five dataset means, but
  only slightly, and its `@10` dataset mean never beats CPARMS-WMF.
- Across-seed spread is modest. The largest CPARMS-WMF `ndcg_all@10` standard
  deviation is Beauty's 0.0018 (per-seed range `0.0451`-`0.0493`); the
  `interaction_1` group varies more, especially on Beauty and Instruments.
- Runtimes are recorded in minutes. CPARMS signal generation costs at most
  ~0.22 min per fit, and a full CPARMS-WMF final fit takes ~0.33 min (Beauty)
  to ~8.82 min (Instruments), roughly 3.1x to 14.2x Standard-WMF and 2.1x to
  6.6x CoFactor-WMF.

## Setup

The reproducible reference environment uses Python `3.13.5`; this version is also
recorded in `.python-version`. Exact package versions are pinned in
`requirements.txt`.

Create and activate a virtual environment from the project root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Running

If the experiment CSV files have not been generated yet, preprocess all five raw
Amazon dumps first:

```powershell
python database/preprocess.py
```

Start Jupyter from the project root:

```powershell
jupyter lab
```

Then run `notebook_experiments.ipynb` for dataset EDA, hyperparameter
search, final retraining, test evaluation, and Excel export.

The notebook uses relative paths such as `./database/csv` and `./results`, so the
project root must be the working directory.

The default experiment is computationally expensive: 5 seeds x 5 datasets x 30
random-search rounds x 3 tuned models is 2,250 tuning fits, plus 100 final
test fits. Reduce `SELECTED_DATASETS`, `MODEL_PARAM_KEY`,
`N_ITER_RANDOM_SEARCH`, or `EXPERIMENT_SEEDS` for a smaller run.

## Comment Conventions

Python source files use one consistent comment structure:

- Begin each module with a concise sentence describing its responsibility.
- Document each callable with an `Inputs:` block followed by one `Output:` line.
- Use `Inputs: None; ...` when a callable has no explicit arguments but reads other input.
- Label multi-stage logic as `Step N:` and nested stages as `Step N.M:` starting at `1`.
- Reserve ordinary sentence comments for decisions, constraints, and non-obvious formulas.
