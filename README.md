# CPARMS_WMF

**Author:** Peerapat Tancharoen, KMITL

CPARMS_WMF is a notebook-driven recommendation experiment under sparse implicit feedback.
It compares standard Weighted Matrix Factorization (WMF) with WMF variants that
use item co-occurrence signals or CPARMS association rule signals. The experiment
and its dataset EDA export are generated by `notebook_experiments.ipynb`.

## Models

The current notebook setup enables seven feature-free recommendation models.

| Notebook key | Model | Implementation | Role |
| --- | --- | --- | --- |
| `01 MostPop` | MostPop | `model/base_model/mostpop.py` | Deterministic global positive-popularity baseline. |
| `02 Standard-WMF` | Standard-WMF | `model/base_model/wmf_standard.py` | ALS-trained implicit-feedback WMF. |
| `03 NeuMF` | NeuMF | `model/base_model/neumf.py` | Vanilla GMF-plus-MLP neural collaborative filtering model. |
| `04 LightGCN` | LightGCN | `model/base_model/lightgcn.py` | Vanilla normalized bipartite-graph propagation with pairwise training. |
| `05 CoFactor-WMF` | CoFactor-WMF | `model/signal_gen/generator_sppmi.py`, `model/base_model/wmf_cofactor.py` | WMF with shared item factors regularized by an item-item SPPMI term. |
| `06 CPARMS-WMF` | CPARMS-WMF | `model/signal_gen/generator_cparms.py`, `model/base_model/wmf_cparms.py` | Full model: association rules with both user-cluster and item-cluster antecedents. |
| `07 CPARMS-Only` | CPARMS-Only | `model/signal_gen/generator_cparms.py` | Rules-only ablation that ranks the normalized CPARMS signal directly, without WMF. |

## Feedback Matrices

`util/feedback.py` centralizes the conversion from raw ratings to the matrices
used by training and evaluation:

```text
Y = raw non-negative ratings, values preserved
B = seen interactions, where Y != 0 becomes 1
L = liked interactions, where Y > 3.0 becomes 1
```

Ratings strictly greater than `3.0` are positive feedback. For integer star
ratings, this is equivalent to keeping ratings `4` and `5` as positives.
Ratings `1`, `2`, and `3` remain in `Y` and `B`, so they affect duplicate
collapse, seen-item masking, and observed-history activity groups, but they are
not positive WMF, CPARMS, SPPMI, validation, or test targets.

## Methods

### Standard-WMF

`WMF_Standard` factorizes the binary positive-feedback matrix `L` with ALS.
Unobserved and non-positive pairs use confidence `1`; positive pairs use
confidence `1 + alpha`. The model stores user factors in `P`, item factors in
`Q`, and scores a user with `Q @ P[user_idx]`.

### Vanilla baselines

`NeuMF` combines a generalized matrix-factorization branch with a separate MLP
embedding branch and learns from positive examples plus sampled non-positive
items using binary cross-entropy. Its canonical tower includes the concatenated
MLP embedding width and halves each successive layer down to the predictive
factor count. It is trained end-to-end without CPARMS input or pretraining.
The official 4:1 sampling ratio, global epoch shuffle, Adam settings,
initializers, sigmoid output, and default batch size are retained.

`LightGCN` constructs a symmetric normalized user-item graph from `L`, averages
the initial embeddings with embeddings propagated through the configured number
of graph layers, and optimizes the resulting rankings with the BPR objective.
It uses the official normal initialization (`std=0.1`), the upstream Python
fallback uniform-user sampler, half-scaled embedding regularizer, Adam optimizer,
and 2,048-pair batch. The
random search uses 30--100 epochs. The pinned first round is capped at 100
epochs instead of the upstream 1,000-epoch budget to keep baseline sweeps
practical.

The source-to-local parameter mapping used in the regression tests is:

| Baseline | Source-equivalent local formulation |
| --- | --- |
| Standard-WMF | Binary target `L`; confidence `1 + alpha * L`; exact Hu/content-WMF ALS normal equations. |
| CoFactor-WMF | `alpha = c1/c0 - 1`, co-occurrence weight `gamma = 1/c0 = 1/ell`, and every regularizer divided by `c0`; the shared item factor is updated jointly from WMF and SPPMI. |
| NeuMF | Separate GMF/MLP embeddings, MLP input width `layers[0]`, elementwise GMF product, ReLU tower, concatenated prediction layer, BCE/Adam, and four negatives per positive. |
| LightGCN | `D^-1/2 A D^-1/2`, mean of layer `0..L`, pairwise softplus/log-sigmoid objective, and L2 only on sampled ego embeddings with the upstream one-half scaling. |

The rating-to-positive threshold, temporal full-catalog evaluation, validation
selection, and independent RNG streams that preserve item initialization when
padded users are added are experiment-protocol
adaptations and are not behavior copied from those repositories. LightGCN uses
the upstream Python sampling path rather than the optional C++ extension. The
experiment's outer validation search also replaces upstream
in-training checkpoint/early-stopping behavior; selected models are retrained for
their configured fixed budget.

### CPARMS Signal

`Generator_CPARMS` builds a sparse user-item signal from a training matrix:

1. Canonicalize raw feedback as `Y`, seen interactions as `B`, and liked
   interactions as `L`.
2. Add individual liked-item tokens from `L`.
3. Optionally fit KMeans user clusters on active positive-history rows and add
   user-cluster tokens.
4. Optionally fit KMeans item clusters on active positive-history item rows and add
   liked-item-cluster presence tokens (E).
5. Combine token blocks in the transaction layout `[L | U | E]`.
6. Count directional token pairs over observed fit users only and keep only rules
   whose consequent is an individual item token; cluster tokens provide antecedent
   context only. Padded evaluation users never affect the rule statistics.
7. Filter rules by `min_support`, `min_confidence`, and `min_lift`.
8. Score retained rules by rule `confidence`.
9. Split confidence contributions into generic user-cluster rules and
   personalized item/item-cluster rules, then remove previously seen items
   from both families.
10. Add the generic and personalized rule-confidence contributions into item
    scores.
11. Optionally normalize with per-row `row_max` or log-damped per-row
    `log_row_max` (`log1p` before row-max scaling).

The CPARMS-Only ablation uses this final normalized signal matrix directly as
its ranking scores. It has no latent factors, WMF loss, or factor-training
hyperparameters. CPARMS-Only and CPARMS-WMF see the same sampled generator
configurations in each validation round, and the notebook reuses the generated
signal between them during tuning.

`WMF_CPARMS` adds a signal term over the nonzero entries of the CPARMS signal
matrix `S`, weighted by `gamma`. During the new-user experiment, shared item
factors are learned from observed fit users only. Evaluation-only users are then
folded in from their learned CPARMS signal while the item factors remain fixed.

### CoFactor Signal

`build_item_sppmi_matrix()` builds an item-item SPPMI matrix from positive
training history. It counts off-diagonal item co-occurrences, converts counts to
PMI, and keeps positive values after subtracting `log(negative_samples)`.

`WMF_Cofactor` combines the WMF loss with an item-item SPPMI term. It updates
user factors, item factors, context factors, item/context biases, and the global
co-occurrence bias used by the upstream `CoFacto` model. The implementation uses
an algebraically equivalent confidence normalization: upstream `(c0,c1)` becomes
`(1,c1/c0)`, while the co-occurrence and regularization weights are divided by
`c0`. If `fit()` receives no item-item matrix and
`gamma > 0`, it builds SPPMI internally; the final test notebook builds SPPMI
explicitly for positive `gamma` so signal-generation runtime can be logged separately.

The paper scales the WMF part of the objective by a relative scale `ell`. This
implementation uses the algebraically equivalent `gamma = 1 / ell` on the
co-occurrence part. As in upstream `CoFacto`, context regularization is a
separate hyperparameter rather than being tied to user/item regularization.

## Experiment Workflow

`notebook_experiments.ipynb` runs the complete experiment:

1. Load selected CSV files from `database/csv/`.
2. Sort all events globally by `timestamp`, using original row order to break
   timestamp ties.
3. Split rows into chronological train, validation, and test partitions targeting
   `70/10/20` ratios. Cut points are snapped to the nearest unique-timestamp
   boundary, so no single timestamp straddles two partitions and the realized
   ratios can drift slightly from the targets.
4. Index tuning matrices over train and validation users, padding users that first
   appear in validation as empty train rows. Keep only train-known items.
5. Run reproducible random hyperparameter search for each seed.
6. Select each seed/dataset/model configuration by validation overall `NDCG@10`.
7. Index final matrices over train, validation, and test users, padding users that
   first appear in test as empty train+validation rows. Keep only items known in
   train+validation.
8. Retrain the selected configuration on train + validation.
9. Evaluate on test at `K = 10, 20, 50, 100, 200`.
10. Export an Excel workbook with `results`, `mean_sd`, and `dataset_eda` sheets.

The split targets **new-user cold start**. Every evaluation user is represented in
the stage matrices, including users with no fit-window interaction. The item
catalog remains fit-window-restricted: validation uses train-known items and test
uses train+validation-known items. Interactions on future-only items are excluded
from ranking because item cold start is outside this experiment. Empty padded user
rows do not contribute to CPARMS clustering/rule statistics or shared item-factor
training; they receive scores only after the fit-window parameters have been learned.

The CSV inputs are expected to be deduplicated at the `userid,itemid` level.
`_build_sparse_matrix()` still defensively collapses duplicate user-item events
inside a partition to their maximum rating.

Within each random-search round, Standard-WMF and CPARMS-WMF share sampled
`latent`, `lambda_rate`, `n_sweeps`, and `alpha`. CoFactor-WMF uses a
source-aligned factor/iteration/confidence space and samples its own `gamma`.
CPARMS-WMF additionally samples its rule thresholds,
normalization, and cluster counts. CPARMS-Only uses that same rule-parameter
sample without the WMF-only parameters. CoFactor-specific parameters are drawn from
their own random stream, independent of the shared stream used by Standard-WMF
and CPARMS-WMF, so adding or removing CoFactor cannot shift the values the other
models receive.
`random_state` is not sampled: every WMF variant, and the KMeans step inside the
CPARMS generator, receives the experiment seed itself. Initialization is
reproducible, while separate user/item streams ensure that padding evaluation
users cannot shift shared item initializations. Standard-WMF and CPARMS-WMF use
identical initial factors whenever their sampled dimensions match. MostPop is
deterministic and takes no seed.

## Evaluation

`experiments/all_ranker.py` computes NDCG for users with at least one relevant
evaluation item (`rating > 3.0`) in the fit-known item catalog. This includes
evaluation users with zero fit-window interactions. All items stored in the
training matrix are removed from each user's candidate list, including ratings
`1`, `2`, and `3`. Score ties are resolved deterministically by item index.

Historical activity groups are built from all observed interactions in `Y`/`B`:

| Group | Historical interactions |
| --- | --- |
| `interaction_0` | 0 |
| `interaction_1` | 1 |
| `interaction_2` | 2 |
| `interaction_3_plus` | 3 or more |

`model`.


Parameter columns depend on the enabled models; unused model-specific parameter
columns are blank. Because MostPop is not tuned, its rows carry no hyperparameter
values and its `validation_selection_score` is `NaN`. CPARMS-Only rows contain
only the generator hyperparameters, report `model_runtime = 0`, and include rule
generation under `s_mat_runtime`. `s_mat_runtime` is `0` for
every model that generates no auxiliary signal matrix: MostPop, Standard-WMF,
NeuMF, and LightGCN never build one, while CoFactor skips
it only in the degenerate `gamma = 0` case. The default
hyperparameter search never samples that case — CoFactor draws `gamma = 1 / ell`
with `ell` in `{0.01, ..., 10}`, so `gamma > 0` on every trial and CoFactor always
builds an SPPMI matrix with a nonzero `s_mat_runtime`. Runtime values are recorded
in minutes.

Metric columns are appended in cutoff order for each `K` in
`10, 20, 50, 100, 200`:

```text
ndcg_all@K
ndcg_user_interaction_0@K
ndcg_user_interaction_1@K
ndcg_user_interaction_2@K
ndcg_user_interaction_3_plus@K
```

### `mean_sd`

One row is written for each `dataset_name` x `model`. This sheet aggregates the
metric and runtime columns from `results` across seeds.

Identifier columns:

```text
dataset_name
model
seed_count
```

`seed_count` is the number of distinct seeds contributing to the row, so a
partial run is visible in the sheet itself.

Aggregate columns follow this naming pattern:

```text
<metric_or_runtime>_mean
<metric_or_runtime>_sd
```

The aggregated fields are every NDCG column listed above plus:

```text
s_mat_runtime
model_runtime
total_runtime
```

The `_sd` columns are the sample standard deviation across seeds (pandas `std`,
`ddof=1`). They are written as values, not formulas. A single-seed run leaves
them blank (`NaN`).

### `dataset_eda`

Three rows are written for each enabled dataset in the final results workbook,
one for each `raw`, `val`, and `test` split:

```text
dataset_name
split
n_users
n_items
n_interactions
n_users_eval
n_future_item_interactions_dropped
n_future_item_positive_targets_dropped
interaction_0
interaction_1
interaction_2
interaction_3_plus
density_pct
sparsity_pct
```

The `raw` row describes the full input dataset; its evaluation and activity-group
fields are blank. The `val` and `test` rows describe interactions retained after
future-only items are removed. Activity groups count all fit-window interactions;
eligibility still requires a positive evaluation target. Consequently,
`interaction_0` contains validation-only users during tuning and test-only users
during final evaluation. The two `n_future_item_*_dropped` columns make the
out-of-scope item-cold-start targets explicit. Density is
`interactions / (users * items) * 100`, and sparsity is `100 - density`.

`SELECTED_DATASETS` maps a notebook key to a CSV path. All five datasets are

| `05_amz_instruments` | `database/csv/dataset_amazon_instruments_5_core.csv` |

Each CSV must contain these columns (additional columns are ignored):

```text
userid,itemid,timestamp,rating
```

Input constraints enforced by `get_temporal_split()`:

- No nulls in any of the four columns.
- `timestamp` must be datetime-typed or ISO-8601 strings (e.g. `2016-11-07`).
  A numeric column is rejected rather than guessed, because its epoch unit
  (s / ms / us / ns) is ambiguous and a wrong guess would silently move every
  cutoff date. Convert with `pd.to_datetime(col, unit=...)` beforehand.
- `rating` must be numeric, finite, and non-negative. The shipped datasets use
  integer stars `1`-`5`.
- At least three distinct timestamp groups must exist, since cut points are
  snapped to unique-timestamp boundaries.

To change datasets, edit `SELECTED_DATASETS` in `notebook_experiments.ipynb`.
To change which models run, edit `MODEL_PARAM_KEY`. It lists every model in report
order and maps each one to its key in a hyperparameter sample; MostPop maps to `None`
because it has nothing to tune, so the random search skips it and it is fitted only at
final-test time.

The supplied CSV files can be regenerated from the Amazon 5-core JSON Lines dumps
in `database/json/` with `database/preprocess.py`. The preprocessing step keeps the four required
fields, converts Unix timestamps to datetimes, drops incomplete rows, and keeps the
earliest review for each `userid,itemid` pair (breaking timestamp ties by higher rating), so a
later re-review cannot move a user's first observed interaction into a later temporal split.
No k-core filter is re-applied after deduplication: the `_5_core` suffix refers to the
published 5-core source dumps, and collapsing duplicate `userid,itemid` pairs can leave
some users or items with fewer than five remaining rows.

## Comment Conventions

Python source files use one consistent comment structure:

- Begin each module with a concise sentence describing its responsibility.
- Document each callable with an `Inputs:` block followed by one `Output:` line.
- Use `Inputs: None; ...` when a callable has no explicit arguments but reads other input.
- Label multi-stage logic as `Step N:` and nested stages as `Step N.M:` starting at `1`.
- Reserve ordinary sentence comments for decisions, constraints, and non-obvious formulas.
